## Blocking issues at this snapshot

1. **P1: ACL crash recovery/serialization is incomplete.** `scripts/private_calibration.py:406–438` backs up original ACL and restores it in finally. That covers ordinary exceptions and its new SIGTERM handler, but not supervisor SIGKILL/crash. The `*-root-acl.json` is recovery information, not an implemented recovery path; the permanent identity lease does not revoke the named ACL or kill/revoke a surviving worker. No global lock prevents overlapping /root changes. `write_private` closes but does not fsync backup/parent before grant. The old SIGTERM handler is restored *before* `api.write(before)`, so a second TERM during restoration can also leave grant installed. Minimal closure: exclusive global ACL lease; durable before/granted ACL plus root inode/worker UID/run identity; exact-match stale-lease recovery that stops prior worker access and revokes run traversal, restores only the recorded grant rather than overwriting unrelated concurrent ACL changes; verify byte-exact ACL restore; keep signal protection through restoration and retain failure evidence. Do not fake “finally handles SIGKILL”. Tests need normal/worker failure/timeout/SIGTERM, stale kill lease recovery, concurrent refusal, restore failure and exact original ACL. No need to add namespace/mount privileges or copy the24GB asset tree.

2. **P1: probes and actual worker have different privilege floors.** `private_gold_job.py:145–152` makes denied_probe use `PR_SET_NO_NEW_PRIVS`; actual `private_calibration.py:643–665` subprocess only sets user/group/extra_groups and starts a session. It does not establish that bit, while `_runtime_probe` only imports libraries. Therefore negative probes do not demonstrate the worker's exact boundary with respect to setuid/file-capability exec. Use a fixed trusted spawn bootstrap setting NoNewPrivs before worker exec and report/verify the actual worker UID/GID/supplementary groups/NoNewPrivs/CapEff. Avoid arbitrary command hooks; no change to model/data semantics is needed. Trusted root launcher alone does not make this probe equivalence true.

3. **P1: traversal scope/negative evidence is not a read allowlist.** Named UID `--x` on0700 /root plus existing0755/0644 descendants permits access to any known public-readable descendant, not only declared model/media/runtime files. No directory listing of /root is granted, and no world permissions are broadened; that is a reasonable constrained traversal mechanism, but cannot be described as an exact read whitelist. Current sealed_sources probe now checks all registered calibration/holdout paths, and model-write plus /root read/list probe exists. Explicit credential and non-allowlisted-private/read-list denial evidence still needs closure using trusted known private paths/sentinels under the **actual worker** boundary. Do not read/print real tokens or chmod public/shared assets; refuse if any sealed source unexpectedly readable. Clarify already-public asset reachability rather than claiming filesystem sandboxing; no network namespace is enforced and report already acknowledges that.
