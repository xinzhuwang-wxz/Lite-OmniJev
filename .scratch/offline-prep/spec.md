# 全项目开卡前资产准备

## Problem Statement
P0后仍有教师/数据/依赖缺失，GPU空等。用户明确要求整个项目所需下载就绪后才开卡。

## Solution
对原方案阶段0–6建立统一离线资产账本，先准备所有可合法获取的必需外部资产和CPU构建工具；来源、容量、哈希和可恢复下载可审计。GPU启动由用户操作，仅在完整准备验收后通知。

## User Stories
1. 作为付费负责人，希望下载和CPU准备全部结束再开GPU，避免空等计费。
2. 作为执行者，希望模型/数据绑定不可变revision与逐文件哈希，断线后可续传。
3. 作为验收者，希望原方案每个命名模型/数据/运行时都能找到准备状态，遗漏必须可见。
4. 作为发布者，希望许可受限、账号依赖、研究专用和禁止来源分开，不因下载等于训练准入。
5. 作为运维者，希望在现有付费盘容量内预留训练checkpoint/派生数据空间，超容量时先给出证据，不自动扩容。
6. 作为用户，希望后续训练生成的LoRA、校准和量化产物明确列为待生成，不虚称下载缺失或提前完成。

## Implementation Decisions
- 复用现有资产清单/哈希下载接口、数据来源准入登记和独立环境；外部下载与正式训练准入分离。
- 覆盖五个既定基线模型、原方案数据来源与评测集、服务/训练/多模态/端侧必需构建依赖。
- 不提前放量或训练；阶段4数据比例待前三阶段实测，先固定可复用原始来源，派生样本按阶段构建。
- 固定下载量及最坏磁盘预算，保留已有缓存；错误/续传记录不泄露凭据或签名URL。
- 无账号/许可来源或精确分母不明的项目保持blocked，禁止标记“全部齐备”。内部封存只由独立gate接收，不让开发代理下载读取答案。

## Testing Decisions
以资产CLI/离线检查为公共验收接口，复用资产哈希/数据契约行为测试。真实下载报告必须给出命令、退出码、revision、哈希、bytes和环境。断线恢复不得覆盖坏文件；缺失项必须使开卡准备验收失败。

## Out of Scope
自动开关实例、购买磁盘/服务、接受账号条款、生产部署、降低阶段门槛、阶段5b/探索项、下载禁止模型或许可未清训练混合载荷。

## Further Notes
用户已授权自主spec/拆票/triage，不重复技能默认访谈与逐票确认。全项目下载范围取代仅S0下载范围；不改变S0–S6训练顺序。
