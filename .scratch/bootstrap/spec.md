# M0：本地与无卡准备规格

Status: ready-for-agent

## Problem Statement
仓库只有设计方案和 LICENSE，没有可执行基线、状态机或可复现环境；用户希望 agent 承担研发，只在租卡等必要节点介入。

## Solution
先构建不依赖 GPU 的真实数据契约、读出与评测工具、资产准备和恢复工作流，给出经过验证的无卡交接。后续必须用真实基座完成 P0 与训练阶段门槛。

## User Stories
1. 作为负责人，我希望每轮读取持久状态，换会话后仍可接续。
2. 作为执行者，我希望只有依赖完成且无人认领的票可领取，避免重复写入。
3. 作为执行者，我希望独立任务在独立 worktree 完成，验证后集中整合。
4. 作为训练者，我希望输入样本类型、标签和来源可校验，坏数据不能静默通过。
5. 作为训练者，我希望 U 概率与条件答案分布分离，不把弃权当作确定答案。
6. 作为评测者，我希望门槛缺指标或非有限数时失败，不被占位结果蒙混。
7. 作为用户，我希望先准备无卡环境与下载，收到可以开卡的证据后再付 GPU 费用。
8. 作为用户，我希望账号、生产和范围变化才找我，其他可逆工作自动继续。
9. 作为使用者，我希望实际命令、接口与文档一致，CPU 测试与真模型测试分开报告。
10. 作为接手者，我希望知道后续阶段何时拆票，最终有跨功能整合和终局验收。
11. 作为维护者，我希望一次核验上游 revision 和许可后复用缓存，减少外部请求。
12. 作为负责人，我希望每轮有真实工具产出，已证实的全局外部阻塞不被空转掩盖。

## Implementation Decisions
采用 Python 3.11 + uv 锁文件；Pydantic 数据契约、pytest、ruff、mypy；FastAPI 网关后续按官方 SDK 契约落地。
唯一票源为本地 Markdown；triage 标签和执行状态正交；初期无需数据库或云基础设施。
原生 goal 驱动会话中的持续推进；恢复依靠仓库状态，不声称 app 关闭后自动运行。
先单题单序列；打包优化等到阶段 2 且 logit 等价实测通过。保持原方案阈值和三档交付范围。

## Testing Decisions
公共接口为样本验证、概率读出、指标/gate、资产 CLI、HTTP API；行为测试覆盖非法输入、失败退出与可重现结果。
首批无既有测试可复用；CPU 合成夹具只能证明工程行为。真实模型、性能、SDK 和浏览器结果独立收集。

## Out of Scope
本里程碑不训练大模型、不租卡、不付费、不公开发布，不建立生产计费/Kubernetes，不宣称 SOTA 或 GPU gate 已通过。

## Further Notes
后续里程碑按原始方案阶段门槛逐步细拆；原文对人工放行的常规环节由用户新授权改为 agent 自动门槛验证，重大方向/阈值/预算仍由用户决定。
