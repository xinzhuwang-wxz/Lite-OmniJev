## 推荐调整方向
1. 模板/token映射、选项顺序、漏token、归一化和p(U)公式作为确定性契约，严格回归。
2. FP32跨实现的<0.001作为高精度诊断基准；低精度部署采用独立、显式的精度预算，不以此强迫改引擎。
3. 低精度同时报告含U联合分布TV、p(U)偏移、条件概率偏移、top-1变化、Score期望分变化；按实际拒答/自动化决策边界分层。不能删掉不利样本或隐藏API条件分布漂移。
4. 业务放行还要有准确率差、ECE/Brier变化、coverage@risk及高置信翻转；容许量从业务错误成本/风险预算推导。
5. 新容差先在独立的代表性开发集上定标，包括低margin、各p(U)区间、不同选项数和题型，再冻结规则并用另一批未参与定标的数据验证。100条训练fixture不能承担生产门槛定标。
6. 基座异常保留独立调查项；先形成新验收契约和ADR，再更新gate/票据，不能事后把阈值设到现有最大误差之上。

## 下一批实测协议（冻结数据后才看新结果）
- 两个独立的程序真值开发批次：定标与确认各100个样本族、每族一题；不使用或读取产品封存集，不做训练。
- 每批Choice60（2/3/5/10/20选项各12）、Noul20、Score20（2/3/5/10级各5）；每种题型覆盖信息充分、必要事实缺失、矛盾事实，预先规定真值。
- 采用未进入十步训练的任务生成族，按生成族而不是仅文本/数字去重拆分；若无法满足独立性先修数据，不用训练样本改名冒充验证样本。
- 真值由确定性规则计算并审查，记录schema、题型、选项数、来源/生成器版本、样本族、训练重叠检查及内容哈希。仅能代表这些程序任务，不能声称覆盖真实多模态业务。
- BF16 HF与未修改的vLLM TRITON运行同输入、同adapter，各完整执行两批；报告逐题概率、p(U)、联合TV、答案并列变化、Score期望值和实际真值表现。
- 定标批次统计低margin和p(U)中间区域实际覆盖。若缺少边界样本，报告覆盖不足并在定标侧补充；确认侧不能按输出筛掉失败题。
- 候选低精度验收规则必须在读取确认批次推理结果前写入独立ADR/版本配置，并明确仍需用户决定的数值变更；确认失败则保留失败版本，不能回看后调阈值重称独立验证。
- 100例零翻转也不足以支持极低风险声明：独立同分布假设下，单侧95%零失败二项上界约2.95%；模板相关性会进一步削弱结论。生产样本量需由容许错误率与覆盖要求推导。

可复现实测影响分析：
`uv run python -m scripts.parity_impact --reference reports/p0-adapter-hf-001.json --candidate reports/p0-adapter-vllm-triton-001.json --output <新的报告路径>`
该命令从raw logprobs核对概率、检查100题身份/provenance，输出analysis-only，永不覆盖已有报告；不会改变原验收脚本的判断。跨平台libm重算允许rel_tol=1e-12/abs_tol=1e-15，仅作报告完整性容差，远小于引擎门槛。
