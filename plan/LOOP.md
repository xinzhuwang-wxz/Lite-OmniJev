# 可恢复工程循环

## 驱动方式

此会话可用原生 get_goal/create_goal/update_goal；已创建终局 goal。`/goal` 启动词是用户指令入口，具体 UI 若不识别斜杠则整段作为普通消息发送，agent 使用原生工具。
不依赖不存在的 `/loop` 插件，不启动 OMX/superpowers runtime，不配置定时 automation。
原生 goal 在当前工具运行环境内提供继续机制；STATUS 提供跨压缩/跨 session 恢复。App 关闭、账号额度、网络或用户阻塞不能保证后台继续；新 session 用启动词恢复。
只在终局证据成立时 complete；遇等待用户按工具要求处理 blocked，不把阶段结束或 CPU 全绿当 goal 完成。

## 每轮算法

1. 读 AGENTS、STATUS、当前里程碑规格与队列；核查自己创建的作业/worktree，恢复真实状态，不能只凭上轮文字判断进程结束。
2. `scripts.loop validate` 检查依赖/状态；计算 frontier：ready-for-agent + open + 无owner + 所有 blockers done。
3. 有 frontier：以业务闭环为单位冻结范围和验收，主会话串行 claim（票、owner、绝对worktree路径、模块范围），再分派独立任务。并行数按资源，通常≤3；同模块唯一写者。
4. 执行中批量完成相关改动和定向测试；新阻断问题建修复票/依赖，非阻断另建票不扩大当前范围。
5. 子代理报告 commit、测试输出、限制；leader 在主工作区整合并跑批次相关 lint/typecheck/build/test/真实载体验收。必要 review 在里程碑/高风险接口统一做。
6. 通过则勾选验收、链接证据、Execution=done，释放owner；失败保存证据，修复当前业务链，禁止用 skip 或改阈值逃过。
7. 无 frontier 且里程碑未完：恢复claimed业务闭环中的下一可执行步骤；只有独立产物/责任/外部阻塞确需独立管理才新增票。模型、来源、探针和普通修复不逐项拆票；已有外部阻塞不重复拆票。实际作业仍运行才等待。
8. 当前里程碑票全部完成：依 docs/02-project.md 轻量验收+集成票，先删过时 AGENTS 再补经验，写 plan/handoff-日期-里程碑.md，然后展开下一里程碑。
9. 所有里程碑达到出口：执行 FINAL 票，发现缺陷建票修复并重验，未解决问题数为0且终局证据齐全才交付。
10. 每轮结束原子更新 STATUS（里程碑、票/owner/worktree、阻塞、待我决策、下一步、证据）与必要票据；必须有工具证据，可为已验证阻塞，不能仅说“继续推进”。

用户2026-10-14要求收敛：路线以DELIVERY-PLAN.md为准。常规修复只跑相关行为测试；一批合并后按需做静态检查/构建；完整模型门槛与独立review集中在里程碑出口。相同代码/数据的有效证据复用，不按轮次重复全检，不为每个小切片创建handoff。失败GPU配置停止后先读已有profile/时序证据，形成具体改进依据才启动下一不同候选，不穷举配置。

## 状态与恢复规则

票据是任务状态源；STATUS 是人可读调度快照，不能与票矛盾。每轮结束检查两者。
triage Status 和 Execution 分开；仅受票据依赖限制的任务用open+Blocked by，依赖完成即自动进入frontier。blocked用于额外外部/信息/未展开门槛，恢复时须有解除证据，不能无限留在blocked或伪装ready。
新会话发现 claimed：先检查 agent/process/worktree；确认执行者结束或不存在后记录恢复理由再转 open，保留修改。
用户只改变当前分支约束时保留总体目标；任何门槛/范围改变写 ADR 并有用户依据。
原生 goal 状态与磁盘状态冲突时报告差异，按工具真实状态更新；没有 native goal 的新会话按原目标创建，不假装旧 goal 被迁移。

## 无卡→开卡→关卡

A. 本地：代码、锁文件、数据 schema/合成真值、CPU测试、官方 tokenizer/template 探针、资产 manifest 和部署命令；不下载装不下的权重。
B. 用户租无卡实例后：核验 Linux架构/磁盘/网络，设置持久缓存；固定revision下载基座、必要教师和本阶段数据，校验哈希/许可/split，锁训练和服务独立环境，准备GPU作业与断点恢复。
C. 只有必需下载完整、当前无卡可自主完成的CPU准备结束、代码/数据/命令/预算/续跑齐备才通知用户“可切有卡”；当前实例资源受限且已留失败证据的检查列为切换后首批前置，不形成模式切换依赖环。账号/许可/人工身份缺口保持显式，对应训练/阶段准入仍阻塞；不能说已验证GPU兼容。
D. 用户开卡后：小规模环境/模型 smoke→P0真实10步闭环→S0全部门槛；失败先诊断，不盲目长跑；逐步推进预算内训练。
E. GPU作业结束：检查训练/服务进程、检查点和报告落持久盘、记录续跑位置，通知用户关卡；不代用户执行关机/删除实例。

## 需要用户时

记录 Decision ID、必须用户做的动作、理由、已准备证据、阻塞哪些票、可继续哪些票。
只发一次具体通知；有新证据才再通知。凭时间流逝不能推定批准。
若所有剩余票均有已证实外部阻塞，保存交接并结束当前轮；不无意义 sleep、空跑命令、制造票或声称交付。

## 节约外部调用

本地票据/提交是每轮产出，远端不是；不自动 push。
同一外部源一次抓取后记 revision/日期并复用；CI 只在明确远端任务运行时有限等待，不高频查询。
