# 发布宣传与 Demo 方案(宣传角度)

## 核心叙事(一句话)
"别人还在打字思考,我们已经给出带概率的答案。"——单次前向、六模态、带校准概率的类型化决策。

## Demo 1【主打】同题对拍:通用大模型流式 vs 我们瞬时
- 形式:左右分屏录屏。同一道多模态题(截图/视频题最抓眼):
  - 左:通用开源大 VLM(72B 级,开源可部署的最新款)流式输出——长推理、铺垫、对冲词
  - 右:我们——单次前向,<1s 出类型化答案 + 选项概率条形图(实时渲染)
- 视觉钩子:**左边还在打字,右边已经答完并且给出各选项概率**
- 拍摄:终端分屏(tmux)+ 网页双栏,4K 录屏后裁竖屏(社媒)与横屏(HF/YouTube)
- 需要:开卡日 GPU 跑左侧大模型(现场部署)+ 我们的网关;题库 5 题预选(3 题我们赢、1 题平、1 题如实放——诚实也是记忆点)
- 风险:左侧模型如果答得又快又好,叙事反噬——预跑筛选题目(只选直答形态吃亏、需要长推理的题)

## Demo 2【差异化】校准可视化:"我们不仅答,还知道多信"
- 形式:同一批题的预测置信直方图 + 可靠性图(README 那张 ECE 表的动态版)
- 叙事:"多数模型只给你答案;我们给你的概率是校准过的——它说 90%,就真的九成对"
- 门槛最低:纯 CPU 出图,零 GPU

## Demo 3【广度】六模态快速连答
- 形式:一段 montage,六个模态各一题(文本/截图/图像/音频/视频/图文组合),每题 3 秒出答案+概率条
- 展示品类宽度:一个 adapter 覆盖六模态
- 需要:网关批量跑(开卡日 10 分钟实录)

## Demo 4【诚实】失败案例集(可选,建立信任)
- 挑 2-3 个我们答错的视频题,如实展示 + 说明缺口在哪(事件时序感知)
- HF 社区对诚实披露正向;也可留给技术博客而非主宣传
