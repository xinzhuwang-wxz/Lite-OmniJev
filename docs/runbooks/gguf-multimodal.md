## 踩坑 1:mtmd-cli 后台运行"假死"→ SIGTTIN

问题:llama-mtmd-cli 在 screen/nohup 后台运行时,启动后 CPU 时间冻结(21s 不再增长),
看似"加载超时",600-1800s timeout 杀掉全是僵尸(此前多轮"超时"均为此)。
原因:CLI 启动早期读取 stdin,后台无终端 → SIGTTIN → 整组进程 State=T(stopped)。
解法:所有 mtmd-cli 探针一律 `< /dev/null` + `setsid`/nohup;判断真假死先看 `/proc/<pid>/status`
的 State(T=被停,R=真在算)。

## 踩坑 2:大分辨率 RGBA 截图空输出

问题:screenshot.png(1440×3120 RGBA,450 万像素)在三档全部空输出(f16 同样复现,
与量化无关);普通小图正常。
原因:超出 llama.cpp 视觉编码对该输入的处理能力(RGBA 通道+像素量),上流运行时限制。
解法:RGBA→RGB + 等比降采样(max-side 1344/1008/672 任一)即恢复;修复参数与逐项结论
见矩阵产物 JSON。**发布口径:GGUF 截图输入需先降采样(给出参数),或等待上游修复。**

## 音视频运行参数

f16 音频探针(30s wav):静盒下模型加载 ~8-15 分钟(15G 冷读,与 LFS 写盘争用会拖长),
编码+回答另计;探针一律 `< /dev/null`、timeout ≥1800。Q4 加载 ~3 分钟。视频(16 帧序列)
与音频同量级。CPU 空闲时全部通过;争抢环境下的超时不构成能力结论。
