# Issue tracker: Local Markdown

唯一写入源：`.scratch/<feature>/spec.md` 与 `.scratch/<feature>/issues/NN-<slug>.md`。
远端为 https://github.com/xinzhuwang-wxz/Lite-OmniJev；本地票据可版本化，默认不发 GitHub 请求。
用户已授权自主出规格、拆票、triage 和实现，技能中的常规确认改为文件记录后执行。

每票字段：ID、Milestone、Category、Status（triage 标签）、Execution（open/claimed/blocked/done）、Owner、Worktree、Blocked by、验收清单、证据、范围外。
`Blocked by` 使用同 feature 票号；跨 feature 用 feature:NN。
ready-for-agent 不代表无依赖；frontier 要同时满足 Execution=open、Owner=none、所有依赖 done、验收完整。
主会话串行认领并保存，随后才启动子代理；共享模块只有一个 owner。
子代理在隔离 worktree 修改自己的代码，不争写主队列；整合和验证完成后 leader 更新 Execution=done。
中断后先核查进程和 worktree，禁止凭超时抢占活跃 owner。
triage 记录以 `> *This was generated by AI during triage.*` 开头；评论追加到票的 Comments。
PRs as a request surface: off。
仅用户明确要求同步时批量创建/更新远端 issue，并记录映射，不从两处同时调度。
遇限流或鉴权失败保存响应并退避，不循环刷 gh；本地继续执行。
