# ADR4002(提案,worktree 暂名,main 整合时重编号):目标中心输入 token(跟踪/slot 特征注入)

状态:**proposed,2026-10-16,S4 创新切片产出;仅提案不实现。需 ADR+用户决策方可动工。**
编号 4002 为 worktree 暂名。用户 2026-10-16 指令("性能不达标就做颠覆性创新,架构/训练/推理
全维度")授权提出本方向;但动工仍须本 ADR 获批,因为它是输入接口手术。

## 提案

在冻结 Gemma E4B 输入序列中追加 **目标中心 token**(open-source 跟踪/slot 特征,如
SlotTok/Slot-VLM 式对象中心表征)作为额外输入 token:每个被跟踪对象一组 token,携带
身份/轨迹/时相关量;决策 LoRA 学习在 [对象 token + 原始多模态 token + 问题] 上读出。

## 与"冻结基座只训决策 LoRA"的冲突(逐条)

1. **新增 token embedding**:输入词表扩展或复用保留区 → 基座 embedding 表被修改,
   "冻结主干"边界被突破;slot 编码器本身是新增可训练视觉前端。
2. **官方 chat template**:多模态输入结构从官方 image/audio/video token 扩展为混合序列,
   processor 与模板语义变化。
3. **不改推理引擎**:对象 token 注入需要自定义 processor/前向拼接,服务引擎(vLLM)路径
   需扩展——与"不改推理引擎"冲突。
4. 训推一致:对象 token 在训练与服务两端都须经同一提取器;端侧档需自带跟踪器。

## 预期增益依据(引用分歧结构)

oracle-001:候选/父在 video500 上 96 题分歧(57/39 单侧对)+89 双错;帧采样分歧仅 4%
(DEV50 侧信号)——错误主因是**对象级时序/空间信息未进决策前向**,不是采样方差。
目标中心 token 直接把"哪个对象、何时进出、与谁碰撞"作为显式输入,精确命中 in/out、
before/after、exist/absent 三簇残余错误;SlotTok/Slot-VLM(前沿报告 §4)在图像/视频理解上
已证明对象中心注入的增益——先例存在,**因此本方向是"范式级增量"而非空白**,采用价值
取决于契约成本收益比, novelty 排序低于 I1/I5(报告明确"有先例,不建议先行")。

## 成本(粗估,动工前须实测校准)

- 训练:slot/跟踪器选型+冻结;对象 token 化管线;LoRA 重训全课程。GPU 额外 ~1 课程量级。
- 服务:每视频一次跟踪前向+对象 token 注入;vLLM 自定义 processor 适配;端侧档不可用
  (跟踪器依赖)。
- 工程:processor/引擎扩展评审,回归全模态。

## 需用户决策点

1. 是否解除"冻结主干/不改引擎"约束至"embedding 扩展+processor 扩展"这一档。
2. 端侧档是否接受不可用/降级(或仅 GPU 档启用)。
3. 排序:建议先跑 B1+WSFT/I5 试点(合规、便宜、直击同簇错误),仅当其增量不足时
   再裁决本 ADR——同簇错误先用合规手段拿完,再付契约成本。
