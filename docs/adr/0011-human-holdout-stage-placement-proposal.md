# ADR 0011：暂缓真人封存交付至S4放量前

状态：superseded by ADR0012，2026-10-15。以下是用户进一步澄清前的延期解释，不再生效。原暂缓记录：原proposal路径保留供历史引用。用户针对“保持6000题、双标12000次、逐类κ≥0.7及隔离，只将真人截止S0移到S4前”的结构化问题答复：“我没有啥真人标注的东西，要不先不搞”。按该问题上下文执行为暂缓，不解释为永久删除独立验收。

## 生效决定
- 当前不安排真人标注/独立gate账号，不付费、不外包、不生成替代真人证据。
- 真实人工交付不再阻断S0出口和S1–3；已有全部技术门槛成立后可进入后续小规模训练，仍遵守原质量/回归/校准要求。
- s0:05保持未完成/外部blocked，阶段责任移至S4，成为S4放量前和FINAL的明确依赖。六cohort各1000封存、两真人原始判断共12000、逐类κ≥.7、身份签认及隔离均保留。
- 开发agent不得读取封存载荷，模型标签/合成canary不当人标；现有3000dev样本及历史family/media排除继续生效。
- S0报告必须写明人标尚未执行、按本ADR迁移，不能填κ=1或“人标通过”。未来S4如果用户仍不安排人标，届时以实际证据再次作范围决策，不能自动跳过。

## 执行依据
S1–3使用开发集，封存模型评测原本仅S4/5/6由隔离gate读取；暂缓交付不减少最终独立评测。当前没有真人资源，技术基线全部完成，继续等待并消耗开卡时间没有收益。此决定只迁移交付节点，不授权租卡、开关卡、付费、生产或更换模型。

## 落地
configs/gates.json把holdout_annotation_kappa原阈值原样从S0移至S4，声明S4入口必须完成s0:05；S0集成票移除05前置，FINAL显式依赖05。runbook/STATUS/handoff同步。用户仍要求本session完成S0交接，S1训练交新session启动。

用户随后明确删除新增真人标注要求，当前执行docs/adr/0012-existing-gold-without-new-human-labeling.md；不得继续要求用户到S4找真人。
