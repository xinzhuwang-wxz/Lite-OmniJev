# ADR0019：将官方视觉token预算作为显式可追踪输入配置

状态：accepted-for-integration，2026-10-15；尚未切换产品默认值。

固定E4B资产的官方processor默认280视觉token。Google官方文档 https://ai.google.dev/gemma/docs/capabilities/vision/image 允许70/140/280/560/1120，并通过image_processor.max_soft_tokens控制图像细节。该配置属于官方预处理能力，不替换模型、增加分类头或定制推理引擎；视频帧预算和音频处理不随它改变。

E09独立研究进程在同v2/同dev150上从123/150变为126/150，1120预算耗时68.44秒，默认约35秒；CPU样本实际image token260→1107。达到预设扩量条件，正在image dev500单遍筛查。此证据支持正式接入可追踪配置，不足以证明阶段通过或确定全局默认值。

实施边界：训练配置、评测CLI及服务运行配置显式记录image_max_soft_tokens；不指定时使用官方默认，保持已有checkpoint身份。指定值写入训练checkpoint并参与续训一致性校验；报告区分请求值和有效值。统一配置官方processor，禁止修改资产文件；不影响video processor。运行时不支持配置时明确报错，不能只在API上接受参数却忽略。

采用高预算配置需在相同数据、权重、模板、概率语义下复验image/screenshot双遍及文本回归，检查反事实；并在后续HF/vLLM对齐、校准、发布性能中保持该配置。不得将研究wrapper报告当默认输入或阶段验收，旧基线保留。资源/时延目标按ADR0010使用实测校准，不改质量门。端侧E2B预算另由S6验证，不从E4B收益推断。

用户再次强调Jev式快速、低成本的产品特征：高预算首先用于识别质量瓶颈，不预先决定为最终默认。最终选择必须同时满足质量与真实服务延迟/吞吐/显存证据；训练/评测批次总耗时不当作API单请求性能。达到质量后再评估较低预算、蒸馏或其他阶段内节约方法，不能仅追准确率忽略成本。
